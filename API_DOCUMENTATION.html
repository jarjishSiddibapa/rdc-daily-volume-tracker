Daily Volume Tracker — Public API

Login-based API for external applications to pull production data. Test it in Postman.

Base URL 1. Get a token 2. Volume data (daily / monthly / yearly) Postman setup Response examples Errors

Base URL

Every route in this app — including the public API — sits behind a fixed path prefix. On a local server:

http://localhost:8089/r4x8e/api/v1/...

The rest of this page shows paths as /api/v1/... for brevity — prepend your deployment origin and /r4x8e in your requests.

1. Get a token

POST /api/v1/token

Exchange a username + password (the same credentials used to log into the web app) for a Bearer token. No admin setup needed — any active user account works.

Request body (JSON)

{
  "username": "your_username",
  "password": "your_password"
}

Response — 200 OK

{
  "token": "dvt_x7QpK2mF9...",
  "token_type": "Bearer",
  "expires_at": "2026-07-19T10:58:10",
  "expires_in_seconds": 86400
}
Token lifetime: tokens expire 24 hours after issue. Call this endpoint again to get a fresh one — there's no separate refresh mechanism.

Failure responses

StatusBodyMeaning
400{"error": "username and password are required"}Missing field
401{"error": "Invalid credentials"}Wrong username/password, or account disabled
429{"error": "Too many failed attempts. Try again in N minute(s)."}5 failed attempts from the same IP locks it out for 15 minutes

2. Volume data — daily / monthly / yearly

Three endpoints, one per time granularity. All three share the same shape and the same two query params, and all only ever include active plants.

Shared query params

ParamRequiredDescription
metricNoproduced (default) or invoiced. Toggles between produced volume and invoiced quantity — same two views as the Analytics page's Production/Invoiced toggle.
(period param — see each endpoint below)NoDefaults to the current day / month / year if omitted.

Shared per-plant fields

FieldDescription
plant_codeUnique plant identifier
daily_tracker_namePlant name as used in the daily tracker
erp_namePlant name as used in the ERP system (may differ from tracker name)
plant_nameCombined human-readable name — "tracker (erp)" when they differ
regionArea/region the plant belongs to
is_manual_entrytrue if this plant's volume is entered manually rather than pulled from the ERP sync
volumeThe number itself — produced or invoiced, in m³, for the requested period

2a. GET /api/v1/volumes/daily

Volume for a single day.

ParamRequiredDescription
dateNoYYYY-MM-DD. Defaults to today.
GET /api/v1/volumes/daily?date=2026-07-17
Authorization: Bearer dvt_x7QpK2mF9...

→ 200 OK
{
  "period": "daily",
  "date": "2026-07-17",
  "metric": "produced",
  "count": 2,
  "plants": [
    {
      "plant_code": "PLANT-01",
      "daily_tracker_name": "Example Plant",
      "erp_name": "Example ERP Plant",
      "plant_name": "Example Plant (Example ERP Plant)",
      "region": "Example Region",
      "is_manual_entry": false,
      "volume": 103.5
    }
  ]
}

2b. GET /api/v1/volumes/monthly

Volume totalled over a single month.

ParamRequiredDescription
monthNoYYYY-MM. Defaults to the current month.
GET /api/v1/volumes/monthly?month=2026-07
Authorization: Bearer dvt_x7QpK2mF9...

→ 200 OK
{
  "period": "monthly",
  "month": "2026-07-01",
  "metric": "produced",
  "count": 2,
  "plants": [
    { "plant_code": "PLANT-01", "...": "...", "volume": 4259.0 }
  ]
}

2c. GET /api/v1/volumes/yearly

Volume totalled over a full calendar year (Jan–Dec), plus a month-by-month breakdown so you don't need 12 separate calls.

ParamRequiredDescription
yearNo4-digit year, e.g. 2026. Defaults to the current year.
GET /api/v1/volumes/yearly?year=2026
Authorization: Bearer dvt_x7QpK2mF9...

→ 200 OK
{
  "period": "yearly",
  "year": 2026,
  "metric": "produced",
  "count": 2,
  "plants": [
    {
      "plant_code": "PLANT-01",
      "...": "...",
      "volume": 12000.0,
      "monthly_breakdown": {
        "2026-01": 1000.0, "2026-02": 1100.0, "2026-03": 1200.0,
        "2026-04": 1300.0, "2026-05": 1400.0, "2026-06": 1500.0,
        "2026-07": 1600.0, "2026-08": 1700.0, "2026-09": 0.0,
        "2026-10": 0.0, "2026-11": 0.0, "2026-12": 0.0
      }
    }
  ]
}

Months with no data yet (e.g. future months) show 0.0 rather than being omitted — every plant always has all 12 keys.

Testing in Postman

  1. Get a token. Create a new request: POST to http://localhost:8089/r4x8e/api/v1/token. In the Body tab, choose raw → JSON, and paste: 
    {
  "username": "your_username",
  "password": "your_password"
}
    Hit Send. Copy the token value from the response.
  2. Call a volume endpoint. Create a new request: GET to http://localhost:8089/r4x8e/api/v1/volumes/monthly?month=2026-07 (or /volumes/daily?date=..., or /volumes/yearly?year=...). Go to the Authorization tab, set type to Bearer Token, and paste the token you copied. Hit Send.
  3. Tip: save the token in a Postman environment variable (e.g. {{dvt_token}}) via a small script in step 1's Tests tab, so step 2 can reference Bearer {{dvt_token}} without manual copy-pasting each time: 
    pm.environment.set("dvt_token", pm.response.json().token);

GET /api/v1/volumes/daily?date=bad          → 400 {"error": "Invalid date. Use YYYY-MM-DD."}
GET /api/v1/volumes/monthly?month=bad        → 400 {"error": "Invalid month. Use YYYY-MM."}

General notes

  • Everything here is read-only — there is no write API for external applications yet. Data still goes in only via the web UI or the ERP sync job.
  • Use metric=invoiced on any volume endpoint to get invoiced quantity instead of produced volume — same underlying data as the Analytics page's Production/Invoiced toggle.
  • Responses are sent with Cache-Control: no-store — the underlying data changes throughout the day, so don't cache client-side without your own expiry logic.
  • A GET request to a bare URL without the /r4x8e prefix will 302 redirect to the prefixed one. Harmless for testing, but call the prefixed URL directly to save a round trip.
